# Telemetry protocol v1

Transport is newline-delimited UTF-8 JSON (JSONL). Replay and live log tail use the same parser and state reducer. Each line is an immutable event; timestamps are UTC ISO-8601 strings. Unknown fields are ignored for forward compatibility. Unknown schema versions are rejected.

```json
{"schemaVersion":1,"timestampUtc":"2026-09-22T18:00:03Z","sessionId":"run-id","type":"quest_signal","signal":"ascension.monkey_button_interaction","source":"gsc"}
```

Supported GSC event types: `session_started`, `session_ended`, `heartbeat`, `snapshot`, `mod_loaded`, `variant`, `quest_signal`, `quest_progress`, `pressure_timer`, `luna_progress`, `soul_tank_progress`, `samantha_color`, and `richtofen_cue`. Snapshot fields: `map`, `round`, `playerCount`, `powerOn`; `quest_progress` carries a tracker `signal`, current integer `progress`, and integer `progressMax`, sampled from a stock quest counter. `pressure_timer` carries `secondsRemaining` and `signalValue` (`running`, `waiting`, or `complete`). It is a companion estimate, not the quest's authoritative counter. `luna_progress` carries `lettersCollected` from the quest's own passkey counter (0–4). A drop to zero after a collected letter means the sequence reset; it does not identify why. `soul_tank_progress` contains parallel integer arrays `soulTankFill` and `soulTankMaxFill`; the Moon UI renders one active tube during MPD opening and four during the later soul-fill step. `samantha_color` carries one stable color displayed by all four Samantha Says terminals. `richtofen_cue` carries a readable milestone label when Richtofen reaches the Vril Device during the stock second-tank stage. Color capture and voice-cue timing are source-derived and await live verification. The file transport may generate an internal `transport_status` event when heartbeat data stops or resumes. Variant evidence is an object `{ "kind": "ExplicitVariant|ModLoaded|DvarSnapshot|GameplaySignal", "value": "..." }`. Only `ExplicitVariant` values `vanilla`, `any_player_ee`, and `any_player_ee_sr`, or a positive matching `ModLoaded` identity, currently set the ruleset. DVAR snapshots intentionally do not infer a variant: option values overlap across variants and runtime configuration.

The Ascension observer emits changed snapshots for map, round, player count, and power. It reports the six stock success flags as `stock.success.<flag>` quest signals, which the reducer matches to the map's reviewed flow. It also samples the stock/Any Player EE `level.passkey_progress` value and reports each accepted LUNA letter and resets. Only `stock.success.passkey_confirmed` completes the LUNA step. The `sync_button_pressed` notification is also available as an interaction signal, but it carries no button identity and may repeat while use is held; it never confirms step completion.

The Call of the Dead map-scoped observer emits `zombie_coast` snapshots and the stock success signals for power, the Ultimis door, fuse, each of the four generator flags, the branch objective, submarine sequence, Pure Harmony, Golden Rod recovery, and the final `coast_easter_egg_achieved` notification. The reducer selects Stand-In when one player is detected and Ensemble Cast when there are two or more, matching the stock map script's branch. The Shangri-La observer emits map snapshots, stock flags and stage-completion events that map to the researched quest steps, plus stock counters for matched tile pairs, pressure-plate occupancy, lit gas pipes, correct dials, and correct gongs ringing. The Moon observer emits map snapshots, main controller/step flags, four security-panel completion flags, soul-tank counts, stable terminal colors, Richtofen's stock proximity dialogue cue, and `moon_sidequest_big_bang_achieved`. All map observers write to the same file; the latest map snapshot selects the active flow automatically.

The replay reader consumes complete JSON events from the beginning. The generic file tail begins at the current end; the T5 connection reads the scriptdata file from its beginning, then follows appended records. The T5 tail detects file replacement or truncation and reopens from the new session start. Each staged GSC session-start record has a fresh identifier so replacement is visible even if the new file grows quickly.

## T5 GSC scriptdata

The companion GSC observer writes `raw/scriptdata/ee-tracker.jsonl` using Plutonium's sandboxed T5 file I/O. Compact GSC records may omit `timestampUtc` and `source`; the C# parser adds receive-time metadata and identifies the source as `gsc-scriptdata`. The first record is `session_started`; subsequent records are appended as snapshots, variant evidence, quest signals, heartbeats, and an estimated pressure-pad timer. The WPF app automatically reads `%localappdata%\Plutonium\storage\t5\raw\scriptdata\ee-tracker.jsonl` at launch. If no heartbeat arrives for seven seconds after heartbeat support has been seen, it displays `NO GAME SIGNAL`, since a paused game can also suspend script updates. The location matches the file I/O layout documented by a T5 mod author in [ZPause T5](https://github.com/Xeptix/ZPauseT5#where-settings-are-saved).

Plutonium's changelog documents the T5 file I/O functions and sandbox location. The observer is installed in the map-scoped raw-script folder used by the local T5 setup. Its in-game loading, file writes, and live app updates still require a private-match check. Replay remains independent of the game.
